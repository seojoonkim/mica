# MICA 합성 실행 프로토콜 v1

- origin: `kiheon-ideation`
- 적용 범위: `measurable-candidate → actual synthetic execution`
- 실제 서비스 실행: 포함하지 않음

## 1. 세 표면

| 표면 | 내용 | 피측정 에이전트 |
|---|---|---|
| `agent-visible` | 자연어 요청, 사용자가 알려 준 조건, 공통 안전 정책, 허용 도구의 이름·설명·필수 인자 | 공개 |
| `evaluator-visible` | 최종 상태, 승인 경계, 금지 결과, 안전 인계, 의미 단위 사실 판정 | 비공개 |
| `harness-private` | 합성 계정 상태, fixture, 실패 변형, reset, eligibility, oracle, probe, 내부 식별자 | 반드시 비공개 |

피측정 에이전트는 `agent-visible`만 받는다. 측정 명세 파일, 후보 원장, 평가 JSON schema, 성공 토큰과 내부 ID는 전달하지 않는다.

## 2. 운영체제 격리

실행기는 피측정 프로세스를 별도 작업 디렉터리에서 시작한다. macOS에서는 `sandbox-exec` 정책으로 비공개 저장소 루트의 파일 읽기·쓰기를 거부한다. 직접 경로뿐 아니라 에이전트 작업 디렉터리의 심볼릭 링크로 접근해도 거부돼야 한다.

실행 전 preflight가 다음을 확인한다.

1. 공개 작업 디렉터리는 읽을 수 있다.
2. 비공개 루트의 지정 probe는 읽을 수 없다.
3. 공개·비공개 루트가 서로 같거나 중첩되지 않는다.
4. 결과 영수증에 적용 방식과 두 판정이 기록된다.

preflight가 실패하면 실행하지 않는다. `sandbox-exec`을 사용할 수 없는 운영체제는 별도 사용자, 컨테이너 또는 동등한 파일 권한 격리를 구현하기 전까지 실제 합성 실행 대상으로 승격하지 않는다.

```bash
python3 scripts/mica-isolated-agent-runner.py \
  --private-root "$MICA_PRIVATE_ROOT" \
  --agent-root "$MICA_AGENT_ROOT" \
  --private-probe "$MICA_PRIVATE_PROBE" \
  --receipt "$MICA_ISOLATION_RECEIPT" \
  <피측정 에이전트 실행 명령>
```

## 3. 의미 기반 사후평가

자연어 고지와 최종 보고는 특정 정답 문장과 문자 단위로 비교하지 않는다. 도구는 필수 인자 존재, 상태 전이, 승인, 제출 결속만 fail-closed로 강제한다. 숨은 평가자는 실행 뒤 도구 호출, 권위 있는 readback과 최종 응답에서 요구 사실 충족 여부를 판정한다.

새 실행 계약은 `evaluation.mode=post-hoc-semantic-fact-satisfaction`을 명시한다. 판정할 개념마다 `acceptedRepresentations`를 두어 `0일`, `공백 없음`, `중단 없음`처럼 의미가 같은 표현을 하나의 사실로 취급한다. 사전에 열거하기 어려운 자유 서술의 의미 동치는 독립 평가자가 별도 판정한다. 특정 문구를 맞혀야 다음 도구가 열리는 계약은 하네스 결함이다.

## 4. 실행 완료 조건

다음을 모두 만족해야 한 번의 합성 실행 결과로 집계한다.

1. OS 격리 preflight 영수증이 통과했다.
2. 공개 HTTP 표면 또는 동등한 허용 도구 표면만 전달했다.
3. 비공개 경로와 내부 식별자가 공개 요청·도구 응답·에이전트 출력에 나타나지 않았다.
4. 실제 도구 transcript가 보존됐다.
5. 의미 기반 사후평가 결과가 transcript와 계약 SHA에 결속됐다.
6. 실행 횟수와 통과 횟수를 설계 후보 수, 실제 서비스 실행 수와 분리해 기록했다.

## 5. 현재 한계

- 이 프로토콜의 OS 격리 구현은 macOS에서 검증했다.
- 모델 API 통신 자체는 허용하므로 네트워크 목적지 격리는 별도 실행기 설계가 필요하다.
- 합성 실행 통과는 시장별 성립, 실제 사업자 연동, 실제 서비스 성공이나 공개 벤치마크 편입 승인이 아니다.
- 첫 표준화는 기존 파일럿 결함의 회귀를 닫는 단계이며, 다양한 과업과 모델에서 반복해 실행 신뢰도를 높여야 한다.
