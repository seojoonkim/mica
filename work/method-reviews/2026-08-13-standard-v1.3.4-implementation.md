# standard-v1.3.4 구현 기록

## 목적

std-b11에서 확인된 출처 한계 누락, 의미 판정과 verdict 불일치, controller 직접 결함 기록의 재개 차단, 역할 선점 이전 승인, 수동 브리핑 오기, 짧은 lease와 미완료 역할 park 문제를 다음 빈 표준 배치부터 차단한다.

## 반영한 규칙

1. source review는 정확히 7개 필수 기준을 사용하며 `limitationsHonesty`를 포함한다. source·observation review는 필수 기준 하나라도 fail이면 reject여야 한다.
2. frozen observation은 accepted observation 집합과 정확히 같고 원문 행 SHA-256이 일치해야 한다.
3. `assign-role`이 controller 세대·역할·context에 결속된 토큰을 발급한다. 토큰은 파일 쓰기를 물리적으로 막는 비밀 키가 아니라 `complete-role`의 산출물 채택 게이트다.
4. controller가 직접 작성한 `defect-ledger.jsonl`은 `record-artifact`로 원장화한다. `closure.json`은 기존 종료 예외와 `close` 경로를 유지한다.
5. `role-briefing`은 manifest의 `roleInputAllowlist`와 `roleOutputContract`를 그대로 직렬화한다. controller는 브리핑에 임의 입력을 추가하지 않는다.
6. 기본 lease는 180분이다. 미완료 역할이 남아 있으면 `park`가 실패하며, 모든 해당 역할을 `--abandon-role`로 명시해야 claim 해제와 감사 기록을 남기고 park할 수 있다.
7. 새 규칙은 `standard-v1.3.4`에만 적용한다. std-b9·std-b10·std-b11의 기존 판정 형식과 원문은 수정하지 않는다.

## std-b11 의미 관문 회귀 고정

Claude Code 검토에서 요청한 두 관찰 실패 유형을 생산 스크립트 회귀 검사에 이름 있는 사례로 고정했다.

- `ob-b11-01`: 광고·중개 단계 근거를 계약 기간의 실제 부담으로 넓힌 경우 `needBoundary=fail`과 `verdict=reject`가 결속돼야 한다.
- `ob-b11-02`: 상류 검토에서 부정한 인과 서술을 관찰이 승계한 경우 `noInventedFacts=fail`과 `verdict=reject`가 결속돼야 한다.

두 사례 모두 실패 기준이 있는데 `verdict=accept`로 기록하면 `validate-batch`가 거절한다. 실제 std-b11 원문은 수정하지 않고 parked 회귀 증거로 보존한다.

## Claude Code 검토 반영

Claude Code 검토에서 토큰의 성격을 쓰기 차단이 아닌 채택 차단으로 정정했고, 역할 브리핑의 단일 출처를 출력 schema뿐 아니라 입력 allowlist까지 확장했다. `sr-b11-02`는 controller가 정정하지 않고 다음 배치의 새 독립 reviewer만 별도 판정할 수 있게 유지했다. `closure.json`은 controller record-artifact 허용 목록에서 제외했다.

## 비승격 범위

이 revision은 공정 무결성 개선이다. 후보의 의미 품질, 실제 에이전트 실행 성공, 시장 성립, 점수, 공개 적격, MICA 정본 편입을 승인하지 않는다. std-b11은 parked 상태와 원문 증거를 그대로 보존한다.
