# 종합 판단 — 테스트 조건 상세성의 목적 적합성 (Claude × Codex 종합, 기헌 결정 지원)

- 지위: 종합 보고(정본 아님). 두 런타임의 독립 분석·반박을 controller(Claude)가 종합했다.
- 입력: claude-opinion / codex-opinion(독립) / codex-rebuttal(대조 답변) — 같은 디렉터리.
- 작성: 2026-08-11 (코덱스 응답 수신 후 갱신)

## 결론 한 줄

**두 런타임이 독립 분석에서 같은 결론에 도달했다: 상세 설계는 타당하며 문제는 분량이 아니라
공개 위치다 — "짧은 과제 + 두꺼운 비공개 시험 장치"가 목표이고, 이를 강제하는 구조(전달 묶음
분리·블라인드 리허설·하네스 파생 책임)를 designable 관문에 편입해야 한다.**

## B. 통합 결정안 (codex-rebuttal §5 기반, Claude 합의)

1. 현재 후보 27건 폐기하지 않음.
2. `designable` 판정 요건에 **공개·비공개 분리 검사** 추가.
3. 다음 배치부터 L1·L2·L3 산출물을 **별도 묶음**(agent-visible / evaluator-visible /
   harness-private)으로 생성.
4. 기존 27건은 실행 전 **정적 누출 감사**, 실제 실행 투입분부터 **blind-agent rehearsal**
   (위치: oracle 후·designable 직전) 통과.
5. 자연어 응답 → 내부 판정 레코드 변환 책임은 **하네스**에 있음(에이전트에게 스키마·토큰
   생성 요구 금지).
6. 측정 곤란한 삶의 필요는 **"중요하지만 현재 측정 불가" 원장**으로 보존·주기 재검토.
7. 실행 패키지 격리 4요건(하네스 경로 미마운트·요청에 내부 ID/경로 금지·카탈로그는 요약만·
   canary 비노출).
8. 웹 진행판은 설계 수와 실행 수를 분리 표기.

## C. 기헌이 최종 결정할 항목 — 두 분석 반영 후 잔여

1. **통합 결정안 1~8의 채택 여부** (두 런타임 합의안 — 승인 시 방법 규격 v1.3으로 명문화).
2. **소급 강도**: 코덱스 안(정적 감사 전건 + 블라인드는 실행 투입분만) vs 더 보수적(전건 블라인드).
   합의 권고는 코덱스 안.
3. **사이먼 상정 시점·범위**: 샘플 재구성 후 상정(합의). 비공개 하네스 상세까지 공유할지는
   저장소 공개 정책과 함께 기헌·사이먼 결정.
4. **거절 관찰 재론**: "중요하지만 현재 측정 불가" 원장 신설 승인 및 초기 수록 대상
   (예: std-b3 교통약자 이동지원 계열).
