## 2. 역할 등록 방식

annotation은 닫힌 생산 배치를 수정하는 작업이 아니라 repo-level 포트폴리오에 부착하는 별도 작업이다. 따라서 두 역할은 과거 배치의 `batch-manifest.json`에 소급 등록하지 않고 각 exchange job의 `READY.json`에 정식 등록한다.

- `catalogAnnotator`: packet과 enum, 한국어 지침만 읽고 author staging 작성
- `catalogAnnotationReviewer`: annotation raw-row와 packet을 독립 검토
- `validate-job`: 두 context의 충돌, SHA, exact schema, 판정 불변식 검사
- `apply`: 수락 행만 repo-level 원장에 반영하고 receipt 발급

새 생산 배치가 v1.3.5로 열릴 때에는 동일 역할 계약을 새 manifest revision에도 포함해야 한다. 기존 v1.3.4 배치는 불변으로 유지한다.

## 3. 현재 실제 상태

- 기존 annotation 대상: 파일럿 15건 + 닫힌 배치 41건 = 56건
- 포트폴리오 슬롯: 100개
- 현재 점유 슬롯: 0개
- 첫 작업: `work/mica-scenario-exchange/core20-annotation-001`
- 첫 packet: `KI-P15-001`부터 `KI-P15-010`까지 10건
- 의미 작성과 독립 검토: Claude Code 담당, 아직 미수령
- 다음 작업 자동 시작: 금지

대상 수 `56`은 현재 inventory의 관측값이며 상한이나 고정 schema 값이 아니다. 이후 닫힌 배치의 frozen candidate가 늘어나면 `status`가 새 대상 수를 직접 재계산한다.

## 4. Codex 명령

```bash
python3 scripts/mica-portfolio.py status
python3 scripts/mica-portfolio.py validate-job --job-id core20-annotation-001
python3 scripts/mica-portfolio.py apply \
  --job-id core20-annotation-001 \
  --applied-by-context-id <codex-controller-context> \
  --observed-at <ISO-8601>
python3 scripts/mica-portfolio.py export-public \
  --output work/mica-scenario-portfolio/exports/portfolio-public.json
```

`apply`는 Claude Code가 `CLOSURE.json`까지 작성하고 Codex 검증을 통과한 뒤에만 실행한다.
