# MICA standard-v1.3.5 최종 방향

## 1. 결론

현재 공정의 핵심 철학은 공식 MICA 방법론과 부합한다. 완성형 에이전트 시스템, 현지 생활과업, 권위 있는 최종 상태, 승인 경계, 안전한 정지, deterministic simulator, 계보와 독립 검토는 유지한다.

다음 revision에서는 세 가지를 바로잡는다.

1. 과업 저작의 세 직교 필드를 복원한다.
2. 공개 100칸을 10개 카테고리 x 10개로 고정한다.
3. 공개 후보, 공개 core 100, private holdout을 서로 다른 집합과 상태로 운영한다.

진행 중인 `std-b12`에는 소급하지 않는다. `std-b12` 종결 뒤의 첫 빈 배치부터 적용한다.

## 2. 공식 방법론 대조 결과

### 유지

- 최종 상태를 transcript나 성공한 호출로 대체하지 않는다.
- 승인·신원 확인·결제 경계에서의 올바른 정지와 안전 인계를 완료 유형으로 인정한다.
- 비멱등 재시도는 authoritative readback 뒤에만 허용한다.
- 환경 결함은 에이전트 실패로 채점하지 않는다.
- 작성·검토·동결·비교·측정 역할을 분리한다.
- 피측정 에이전트에는 `agent-visible`만 제공하고 evaluator·harness 상세를 숨긴다.

### 즉시 보완

공식 `current rule`은 모든 과업이 다음 세 필드를 서로 독립적으로 선언하도록 요구한다.

| 필드 | 공식 enum |
|---|---|
| `surface` | `web`, `app-only`, `identity-gated`, `phone-or-in-person`, `mixed-surface` |
| `terminationClass` | `completed-final-state`, `approval-handoff`, `refusal`, `escalation` |
| `declaredComplexity` | `single-step`, `multi-step`, `cross-session` |

완료 배치의 frozen candidate 39건에는 세 필드가 0건이다. 초기 pilot 15건은 과거 형식의 `terminationClass`만 있고 나머지 두 필드가 없다. 따라서 다음 revision에서 candidate review와 freeze의 필수 구조로 둔다.

기존 54건은 frozen row를 수정하지 않는다. 별도 `catalog-annotation` 대장에서 독립 annotator와 reviewer가 공식 enum으로 분류한다.

## 3. 일곱 진단 축의 정확한 위치

공식 일곱 축은 orchestration, model routing, memory, tool/API use, localization, safety, recovery다.

이 축을 candidate writer의 답안처럼 강제하지 않는다.

- candidate 단계: 세 직교 저작 필드만 필수
- measurement design 단계: `expectedDiagnosticAxes`를 사전 선언
- system attempt 뒤: 실행 증거로 `observedDiagnosticAxes`와 실패 원인을 기록
- validated 승격 단계: 공식 `diagnosticAxes`와 market applicability를 갖춰야 함

사전 라벨은 예상 coverage일 뿐 실제 coverage가 아니다. 실행하지 않은 축을 관찰됐다고 표현하지 않는다.
초기 pilot 15의 자유서술형 `diagnosticAxes`는 공식 일곱 축 enum과 같다고 간주하지 않는다. 별도 annotator가 공식 축으로 매핑하고 독립 reviewer가 확인하기 전에는 promotion 근거로 쓰지 않는다.

## 4. 100건은 필수 공개 포트폴리오다

목표는 정확히 100개의 공개 slot이다.

- 10개 카테고리
- 카테고리마다 10개 slot
- 총 100개

이 수량은 선택 목표나 권장치가 아니다. 모든 slot을 실제 시나리오로 채워야 한다.

다만 수량은 품질 관문을 약화시키지 않는다.

- reject·duplicate·hold는 slot을 채우지 않는다.
- 해당 slot은 `empty`로 남는다.
- 새 근거와 새 후보로 다시 생산한다.
- 10개를 넘긴 카테고리의 추가 후보는 research pool 또는 rotating public challenge 후보로 남고 core slot을 자동 점유하지 않는다.

## 5. 세 집합을 분리한다

### research candidate pool

독립 자료에서 생산된 공개 후보의 전체 집합이다. 수량 제한이 없고 reject·hold·비적격 이력도 계보로 보존한다.

### public core 100

10 x 10 고정 포트폴리오다. 각 slot은 다음을 모두 만족한 하나의 서로 다른 후보만 점유한다.

1. accepted frozen candidate
2. 카테고리와 slot ID 결속
3. 세 직교 저작 필드 결속
4. 사후 comparator에서 duplicate가 아님
5. fixture·reset·eligibility·oracle 측정 설계 결속
6. `agent-visible` 분리와 blind-agent rehearsal 통과
7. 원천·관찰·후보·비교·측정 계보 추적 가능

100개 slot이 모두 이 상태가 되면 `public measurable portfolio complete`라고 한다. 이것은 시장 검증, 시스템 성능 검증, 공개 benchmark 결과를 뜻하지 않는다.

### private holdout

public core 100과 별도다. 100개 수량에 포함하지 않는다.

- 현재 공식 상태와 마찬가지로 holdout 수량·비율은 미정이다.
- 기존 공개 54건은 공개 이력 때문에 future holdout으로 사용할 수 없다.
- 실제 holdout은 access-controlled 저장소와 export 차단 장치가 준비된 뒤 새로 저작한다.
- public repo·사이트·artifact에서 `taskSet=holdout`이 발견되면 fail closed한다.

## 6. 기존 54건의 상태

기존 54건을 폐기하지 않는다. 두 상태를 분리한다.

| 상태 | 의미 |
|---|---|
| `public-exposed` | 이미 공개되어 holdout으로 재사용할 수 없음 |
| `core-slot-qualified` | 100칸 점유 조건을 전부 통과함 |

현재 54건은 첫 상태만 확정한다. 100칸 점유는 자동 승인하지 않는다.

별도 annotation·comparison·측정·노출면 관문을 통과한 후보만 core slot에 결속한다. 탈락 후보는 공개 연구 이력으로 남고 slot은 비운다.

## 7. 100칸을 채우는 clean-room 방식

controller만 100칸 ledger를 본다. 다음 batch의 target은 미완료 카테고리와 세 직교 축의 균형으로 정한다.

source researcher와 need writer에게 허용하는 정보:

- high-level 카테고리 이름
- 기존 후보와 무관한 중립적 하위 생활영역
- 목표 `surface`, `terminationClass`, `declaredComplexity`
- 독립 1차 자료 범위와 시장 범위

금지하는 정보:

- 기존 MICA 과제 문안
- 기존 후보와 가까운 과제 ID
- 구체적인 gap 설명이나 정답 상태
- comparator 판정문
- 남은 slot의 기존 내용

세 직교 축은 공식 저작 균형 조건이므로 제공할 수 있다. 자료가 목표 조합을 지지하지 않으면 억지로 후보를 만들지 않고 reject 또는 0건으로 닫는다.

## 8. duplicate 반복의 종료 조건

동일한 category·surface·termination·complexity 브리프가 한 배치에서 slot 적격 후보를 만들지 못하면 그대로 재사용하지 않는다.

controller는 다음 중 하나를 바꾼다.

- 중립 하위 생활영역
- interaction surface
- termination class
- declared complexity
- 근거 source pool

comparator의 구체 후보명과 gap 답안은 작성자에게 돌려주지 않는다. controller에는 family 수준의 `target-exhausted`, `duplicate-heavy`, `evidence-insufficient` 신호만 환류한다.

## 9. 시장 상태와 validated 승격

100칸 완성과 MICA validated 상태를 분리한다.

public measurable candidate는 시장 상태를 과장하지 않고 `marketValidationStatus=unverified`로 둘 수 있다. validated 승격 전에는 다음이 필요하다.

- 공식 market applicability 기록
- 시장 서비스 이용 경험이 있는 local author와 independent local reviewer
- 언어·주소·이름·날짜·통화·결제·신원·휴일·승인 경계 검토
- fixed access parity
- versioned system snapshot
- model invocation, latency, metered cost 계보
- 반복 실행과 불확실성 보고

따라서 100칸을 채우는 일은 필수지만, 100건이 곧 validated benchmark라고 표현하지 않는다.

## 10. 다음 revision 구현 범위

`standard-v1.3.5`는 다음을 한 묶음으로 구현한다.

1. task candidate schema에 세 직교 필드 추가
2. candidate review·freeze validator에 enum·필수성 검사 추가
3. 10 x 10 `portfolio-100` ledger와 slot 상태 validator 추가
4. 기존 54건용 immutable annotation ledger 추가
5. measurement에 `expectedDiagnosticAxes` 추가
6. validated promotion에서 official diagnostic axes와 market applicability 검사
7. public export와 site generator의 holdout fail-closed 검사
8. category-targeted clean-room briefing과 변경 없는 재시도 금지
9. 회귀 테스트와 다음 빈 배치 readiness gate

## 11. 최종 결정

방향 전환은 아니다. 기존의 엄밀한 최종 상태·승인·복구·하네스 구조는 유지한다.

보완의 핵심은 다음 한 문장이다.

> 10개 카테고리 x 10개의 공개 measurable scenario를 반드시 완성하되, 세 직교 저작 필드와 공개·private 경계, 시장·실행 상태를 사실 수준별로 분리하고 수량을 이유로 품질 관문을 건너뛰지 않는다.
