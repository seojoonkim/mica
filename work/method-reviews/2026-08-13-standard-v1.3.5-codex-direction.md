## 사용자 확정 조건

- 공개 과제 포트폴리오는 선택 목표가 아니다.
- 10개 카테고리마다 10개, 합계 100개의 실제 자리를 반드시 채운다.
- 수량을 맞추기 위해 reject·duplicate·hold를 승격하지 않는다. 불합격이면 해당 자리는 빈 상태로 남고 새 후보를 생산한다.
- 진행 중인 std-b12에는 새 revision을 소급하지 않는다.

## 공식 방법론과 로컬 실측

1. 공식 MICA current rule은 모든 과업에 다음 세 직교 필드를 요구한다.
   - interaction surface
   - termination or completion class
   - declared cognitive complexity
2. 완료된 배치의 frozen candidate 39행을 기계 집계한 결과 세 필드가 0/39다.
3. 초기 pilot 15는 terminationClass 15/15지만 interaction surface와 cognitive complexity는 0/15다.
4. 공식 문서의 seven diagnostic axes는 orchestration, model routing, memory, tool/API use, localization, safety, recovery다. 이들은 system/attempt 결과의 진단 설명으로 제시된다. 공식 문구는 모든 task candidate가 diagnosticAxes를 저작 필드로 선언해야 한다고 말하지 않는다.
5. 공식 current status는 public 100이 provisional public-set candidates이고 holdout이 아니라고 명시한다.
6. 공식 문서는 private holdout set이 planned이고 아직 0건이라고 명시한다. export separation code만 구현돼 있다.
7. 지금 공개된 54건은 공개 후보로 생성·배포됐다. holdout으로 지정한 항목을 노출한 증거는 없다.

## Codex 독립 판단

### 채택

- D1은 blocking regression이다. 다음 revision부터 세 직교 필드를 candidate review와 freeze의 필수 계약으로 둔다.
- 기존 39건은 frozen row를 수정하지 않고 별도 annotation ledger에서 독립 catalog reviewer가 소급 분류한다.
- market edition, local authoring/review status, language/register provenance도 별도 상태로 기록한다. 근거가 부족하면 unverified를 유지한다.

### 수정 채택

- diagnosticAxes는 candidate authoring의 필수 수락 조건으로 강제하지 않는다.
- measurement design에서 expected diagnostic coverage를 선언할 수 있고, 실제 run 뒤 attempt evidence로 관찰된 축을 진단한다.
- 단순히 7개 축 라벨을 후보에 붙였다는 이유로 coverage나 품질이 충족됐다고 보지 않는다.

### 반박

- 공개된 54건 때문에 holdout을 훼손했다는 표현은 부정확하다. 공식 방법론 자체가 현재 holdout 0건이라고 밝힌다.
- 54건은 permanent public core 후보로 분류하고, future private holdout은 별도 access-controlled 저장소에서 새로 저작해야 한다.
- holdout은 공개 100칸에 포함하지 않는다. 공개 100과 별도의 비공개 집합이다.
- holdout 수량이나 비율은 공식 문서상 미정이므로 임의 숫자를 만들지 않는다.

## 제안하는 100칸 운영 계약

1. 10개 카테고리 x 10개 slot을 machine-readable ledger로 고정한다.
2. slot 상태는 empty, candidate-frozen, comparison-reviewed, measurement-designed, rehearsal-cleared, market-reviewed, run-eligible처럼 사실 수준을 분리한다.
3. 공개 100 완성의 운영 기준은 100개 slot 각각에 서로 다른 accepted frozen candidate와 사후 비교, measurement design이 결속된 상태다. market validation과 system run은 별도 후속 상태로 표시한다.
4. controller는 빈 slot을 보고 다음 batch의 category를 고른다.
5. source researcher에게는 high-level task family만 공개한다. 기존 과제 문안, 기존 후보, gap 설명, 가까운 과제 ID, slot별 정답은 공개하지 않는다.
6. 후보가 동결된 뒤 comparator가 기존 공개 과제와 같은 카테고리의 frozen candidate를 열어 duplicate·transformation·independent-finding을 판정하고 정확한 slot을 배정한다.
7. duplicate·reject·hold이면 slot을 채우지 않는다.
8. 공개 저장소와 사이트는 holdout artifact를 발견하면 fail closed한다. 실제 holdout 생산은 access-controlled 저장소가 생긴 뒤 시작한다.

## 검토 질문

아래 네 항목만 답하라.

1. Codex 판단에서 공식 방법론을 잘못 읽은 부분이 있는가.
2. diagnosticAxes를 candidate 필수 필드로 두지 않는 판단에 동의하는가. 아니라면 공식 문구상 근거를 제시하라.
3. 공개 100과 private holdout을 별도 집합으로 두고, 현재 54건을 public core 후보로 고정하는 판단에 동의하는가.
4. 100칸을 강제하면서 clean-room 독립성을 지키는 category-targeted authoring 방식에 차단 결함이 있는가.

응답 형식: 합의 / 수정 / 반박 / 최종 단일 권고. 1,200자 이내 한국어.
